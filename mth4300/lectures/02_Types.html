Lecture 02: I/O and Types

Output

You've already seen how to make your program print output using std::cout and the << operator. There's a little technicality about << that's not obvious. When your program uses <<, the output doesn't necessarily print immediately. Instead, it can be stored in the output buffer, which stores the data you want to output to send to the output device later. The idea behind this is that it can be time-consuming to write data directly to the output device, so we don't want to do this more often than necessary. Instead, we save the data and only write it when necessary:

  • When the buffer becomes full, so that we can't store any more data
  • When the program specifically calls for the buffer to be flushed
  • When the program ends
  • When reading input from std::cin, to ensure that prompts are printed before asking for input.

Note that "std::cout << x" actually does two things: it prints out x, and then it returns std::cout. This allows us to chain multiple <<'s together; each << gives back std::cout again so that the next << can use it also: 

#include <iostream>
int main() {
    int a{4}, b{2};
    std::cout << a << b << std::endl; // Prints "42"
    return 0;
}

As you can see if you run the above code, using << does not automatically add any whitespace after printing. Thus the above code prints "42", with no space between the 4 and the 2. If we want a space between consecutive outputs, we must print it explicitly: 

#include <iostream>
int main() {
    int a{4}, b{2};
    std::cout << a << ' ' << b << std::endl; // Prints "4 2"
    return 0;
}

Similarly, if we want a newline, we have to print that explicitly, too. You've already seen one way to do that, using std::endl. Alternatively, you can output a newline character '\n' instead. The difference between these is that std::endl flushes the buffer. This means that you shouldn't use std::endl if you want to create a newline, but don't need the output buffer to be flushed immediately.

You can flush the buffer without writing a newline by outputting std::flush or by calling std::cout.flush().

Input

Just as the data in a variable x can be written to standard output via "std::cout << x", we can get input stored in a variable x using "std::cin >> x". As with output, we can chain these together to get multiple inputs: 

#include <iostream>
int main() {
    int a, b;
    std::cout << "Enter two integers:" << std::endl;
    std::cin >> a >> b;
    std::cout << "Their sum is " << a + b << std::endl;
    return 0;
}

When we use >> to get input, C++ automatically converts it from a string to the appropriate type, if possible. In the above example, whatever the user typed in is converted to an int because the variable we're trying to store it in is an int. (What if the input can't be converted to the appropriate type, e.g., the user types letters when we expected an int? Of course, C++ does provide a way to recover, but we won't worry about it for now.)

When we use <<, data is read from standard input until we reach the first whitespace character. Thus, if the user wants to ask the above program to add 4 and 3, the user can either type "4" Enter "3" Enter or "4 3" Enter. In either case, everything before the first whitespace is read into the variable a, and then everything before the second whitespace is read into the variable b.

If you need to read in an entire line, including spaces, you can use std::getline: 

#include <iostream>
#include <string>
int main() {
    std::string movie;
    std::cout << "What's your favorite movie?" << std::endl;
    std::getline(std::cin, movie);
    std::cout << "I agree! " << movie << " is a great movie!" << std::endl;
    return 0;
}

Types

Next, we'll look at some of the most important types in C++. In order to fully understand them, we'll need to know a little bit about binary.

Binary

As you probably already know, computers store data in binary (i.e., as 0's and 1's). Each 0 or 1 is called a bit, and a group of eight bits is called a byte. A byte is the smallest addressable unit of memory in C++; you can't store a variable in half a byte, or 1.5 bytes, etc.

If you have n bits available to store a positive integer, what's the largest integer you can store? (Whenever I say "integer," I'm referring to the mathematical concept; I'll always call the type "int" instead.) Obviously, the largest integer is 11...11, where all n bits contain 1's. Therefore, the largest integer we can store is

20 + 21 + ... + 2n-1 = 2n - 1.

However, when we store an integer, we usually want to allow for negative values also. The first bit is therefore reserved as a sign bit, which indicates whether the number is positive or negative, but not in the way you might think. Even though 00000010 represents 2, 10000010 does not represent -2. In fact, it represents -126. This way of representing negative numbers is called two's complement, and it's designed so that the computer can do arithmetic with positive or negative numbers without needing special handling for negative numbers.

For example, 11111111 represents -1, because if we add 1 to 11111111, we get 100000000; but the 1 overflows out of the allocated memory, so the computer stores 00000000. Since 11111111 + 00000001 = 00000000, it must be the case that 11111111 represents -1.

Now suppose we have k bytes allocated to store an integer. We know that k bytes is 8k bits, but the first bit is reserved as a sign bit, so we only have 8k - 1 bits available to store a positive number. Therefore the largest positive number we can store is 28k-1-1. The largest negative number that we can store is -28k-1. (If you know how two's complement works, you can check this directly. Alternatively, you could predict this answer by noticing that there are 28k possible values that can be stored by k bytes, and the interval [-28k-1, 28k-1-1] contains 28k integers.)

int

There are several types in C++ that can be used to store integers, but probably the most commonly-used one is int. The C++ standard says that the compiler is required to allocate at least two bytes to store an int, but most compilers allocate 4 bytes. If you want to know how many bytes your compiler uses, run the below code: 

#include <iostream>
int main() {
    std::cout << sizeof(int) << std::endl;
    return 0;
}

This code will almost certainly print 4. If it doesn't, let me know! I'd be curious to know how you ended up with a compiler that doesn't allocate 4 bytes for an int.

Assuming that an int is 4 bytes, what range of values can be stored in an int? According to the formula we found above, that range is [-231, 231-1] = [-2,147,483,648, 2,147,483,647]. If you don't feel like doing the math, you can ask C++ to tell you the limits: 

#include <iostream>
#include <limits>
int main() {
    int min{std::numeric_limits<int>::min()}, max{std::numeric_limits<int>::max()};
    std::cout << "[" << min << ", " << max << "]" << std::endl;
    return 0;
}

What happens if you try to store a value outside of this range in an int variable? You'll instead get the value in [-231, 231-1] which is congruent to the correct value modulo 232; in other words, the compiler will simply ignore any bits that overflow the allocated memory, as mentioned in the 11111111+1 example. If you have a positive number that's only slightly too big, it'll overflow to a negative number, which might make it easy to diagnose the bug: if your program prints a negative number in a situation where it's mathematically impossible to get a negative number, there's a good chance that the reason is overflow. On the other hand, if you overflow by too much, the number might come around to be positive again, making the bug less obvious.

For most real-world applications, you'll never need to deal with numbers larger than 2,147,483,647, which can make it easy to forget that there's an int limit on the rare occasions when you are using huge numbers. Any time you're working with big integers, make sure you take a moment to check whether those numbers will fit inside an int (or just use a bigger type to be safe). For example, the below program prints the wrong answer for 13 factorial. The code is correct, except that an int isn't big enough to hold the number we want: 

#include <iostream>
int factorial(int n) {
    return n <= 0 ? 1 : n * factorial(n-1);
}
int main() {
    std::cout << factorial(13) << std::endl;
    return 0;
}

long long

What if you need to work with numbers too large to fit in an int? There's a larger data type for storing integers, which is called long long. (There's also a long type, but you shouldn't use it.) The C++ standard guarantees that it will be at least 8 bytes; most compilers make it exactly 8. Assuming that long long is 8 bytes, this means that the range of numbers that it can store is

[-263, 263-1] = [-9,223,372,036,854,775,808, 9,223,372,036,854,775,807].

For most practical purposes, you'll never need numbers larger than that.

We can use long long to make a slightly better factorial program. Now it works for 0 <= n <= 20, but even long long isn't big enough for 21!: 

#include <iostream>
long long factorial(long long n) {
    return n <= 0 ? 1 : n * factorial(n-1);
}
int main() {
    long long n;
    std::cout << "Enter n: ";
    std::cin >> n;
    std::cout << factorial(n) << std::endl;
    return 0;
}

unsigned

In many applications, you know that you'll never need negative numbers. In that case, you might not want to waste a bit on a sign bit. C++ lets you do this; if you write unsigned before the name of a type that is typically signed, you get the same amount of memory, but the first bit is available to store larger positive numbers rather than being a sign bit. For example, an unsigned int can hold any integer from 0 to 232 - 1; an unsigned long long can hold any integer from 0 to 264-1.

If you try to store a negative number in an unsigned type, you will get a garbage value similar to what happens if you try to store a value that is too large. For example, the below program prints 4294967295, because that is the maximum unsigned int minus one: 

#include <iostream>
int main() {
    unsigned int n{3}, m{4};
    std::cout << n - m << std::endl; // Prints 4294967295
    return 0;
}

char

The type char is intended to store a single character. You can initialize it by typing the character in single quotes. (Note that unlike Python, single and double quotes are not interchangeable in C++. Single quotes are used for characters, while double quotes are used for strings.) 

#include <iostream>
#include <string>
int main() {
    std::string s{"Hello"};
    char x{s[0]}, y{'i'};
    std::cout << x << y << std::endl; // Prints "Hi"
    return 0;
}

Similar to Python, you can use escape sequences to write character literals with characters that are inconvenient to type normally, such as '\n' (newline), '\t' (tab), '\\' backslash, '\'' (single quote).

A char stores exactly one byte. As far as the compiler is concerned, a char is just a numeric value, which can be converted to/from a character as needed using the ASCII encoding. This means that we can initialize a character as a number. For example, the ASCII value of the newline character is 10, so the below program prints "true": 

#include <iostream>
int main() {
    std::cout << std::boolalpha; // Print bools as text
    char x{'\n'}, y{10};
    std::cout << (x == y) << std::endl; // Prints true
    return 0;
}

We can even do math with characters. (For example, we could Caesar shift characters by adding the size of the shift, except that we need to be careful to make the end of the alphabet wrap around.) However, the result will be an int, not another char, which can result in some unexpected behavior. if you don't cast back to a char: 

#include <iostream>
int main() {
    char x = 'a';
    char y = x + 1;
    std::cout << y << std::endl; // Prints 'b'
    std::cout << x+1 << std::endl; // Prints 98
    return 0;
}

The C++ standard does not state whether a char is signed or unsigned. If that matters to you, you can declare a variable "signed char" or "unsigned char" explicitly.

bool

The C++ data type for booleans is called bool. The C++ boolean literals are true and false. (Note that these are not capitalized, unlike the boolean literals in Python.) In theory, a bool could be stored in a single bit, but since C++ doesn't let us assign a single bit to a variable, a bool is one byte. A value of 0 is treated as false, and anything else is treated as true.

If you try to print a bool, the default behavior is to print 0 for false and 1 for true. We saw above that you can make C++ print "true" or "false" instead using "std::cout << std::boolalpha;".

float/double

There are two types that you can use to store real numbers: float and double; double provides more memory, and therefore more precision, so you should generally use double unless you need to save memory or time. A float provides 6-7 significant decimal digits of accuracy, whereas a double provides 15-16 significant decimal digits. Later in the course, we'll go into more detail about how exactly real numbers are stored (which will also explain where the name "float" came from.)

std::string

We've already seen that the type for strings in C++ is std::string, and that you can define a string literal by writing it inside double quotes. When you use std::string, you should put "#include <string>" at the top of your file. (We saw before that this may not be strictly necessary, because there's a good chance that you have an "#include <iostream>" that imports string for you, but it's still good practice to import string yourself so you're not relying on the details of a file you don't control.)

If you have a string s, the following is a list of things you might want to do with it. All of the examples in parentheses assume that s is "ABCDEFG".

  • s.length() or s.size(): The number of characters in the string. (In the example above, 7.)
  • s[i]: The ith indexed character in the string. (E.g., s[3] is 'D'.)
  • s.substr(pos, count): The substring starting at index pos of length count, or going until the end of the string, if count would take us past the end. (E.g., s.substr(3, 2) is "DE" and s.substr(4, 4) is "EFG".)
  • s.find(t): The index where t starts as a substring of s, or the special value std::string::npos if t can't be found. (E.g., s.find("CDEF") returns 2 and s.find("BCE") returns std::string::npos.)

Perhaps surprisingly, std::string does not provide a good way to convert a string to all uppercase or lowercase; you need to iterate through each character of the string yourself. Since we haven't covered how to do that yet, we won't worry about it for now.

Namespace std

You may find it tedious that we need to write the prefix "std::" in front of so many things. C++ gives you a way around that: you can write "using namespace std;" to tell the compiler to check whether the names that you reference exist in the std namespace (i.e., whether they would refer to something if they had the "std::" in front).

Aside: The :: is called the scope resolution operator because it tells the compiler which scope to look in to find the definition of whatever name comes after it.

Note that "using namespace std" follows scoping rules similar to variables. If you put it at the beginning of your file (immediately after any #include's), then it will apply throughout the file. If you put it inside a particular function, then it will only apply to code within that function. Here's an example: 

#include <iostream>
#include <string>

using namespace std;

int main() {
    string name;
    cout << "Enter your name: ";
    cin >> name;
    cout << "Hello, " << name << "!" << endl;
    return 0;
}

A side challenge, unrelated to namespaces: How could you make this code better?

The advantage of opening a namespace is obvious: it saves some typing, which can also make your code easier to read. The downside is subtle, but serious. The std namespace contains a lot of stuff! When you open it, suddenly your compiler considers all of those names to exist, which can lead to name collisions if you try to give a variable the same name as something in the standard library. Even if you don't have any name collisions today, somebody might add something new to the standard library which has the same name as one of your variables, retroactively breaking your code! For this reason, it is generally recommended that you avoid opening namespaces unnecessarily.

When we start doing practice problems on LeetCode, you'll see that LeetCode opens the std namespace to save you some typing. (However, you won't see "using namespace std" explicitly; it's in the behind-the-scenes code.)

C-style strings

The C language does not have a string data type; instead, it stores a string as an array (i.e., list) of individual characters. Since C++ is based on C, there is old C++ code that handles strings in this way. If you become a professional C++ programmer, you may someday need to edit some ancient code, and then you'll need to work with C-style strings. When writing new code, you should always use the std::string type, which is safer and easier to use.
