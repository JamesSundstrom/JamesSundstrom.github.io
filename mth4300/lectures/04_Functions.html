Lecture 04: Functions

Before we start talking about functions, there are a couple more concepts that will be necessary to fully understand functions.

const

C++ allows you to declare a variable constant using the const keyword. This tells the compiler (and anyone reading your code) that the value of the variable will never be changed. This helps the compiler catch bugs, in case anyone ever tries to modify a variable that wasn't supposed to be modified, and helps your code to be self-documenting, by immediately expressing your intention that the variable be constant to anyone reading your code.

For example, the below code will not compile: 

#include <iostream>
int main() {
    const double PI{3.141592653589793};
    PI = 1.618;
    return 0;
}

Naturally, a variable declared constant must be initialized at the same time that it's declared; we won't be able to change its value later, so we have to give it a value now. That doesn't mean that we need to know the value in advance; the initialized value can be a value that's calculated at runtime, it just can't be changed after it's calculated.

References

C++ lets you define a reference, which is an alias for an existing memory location. This can be a typographic convenience, if a certain memory location is difficult to refer to: if a piece of data is stored in a container in a container in a container, the formula to refer to it may be complicated, so it may be convenient to create a simple reference that refers to it.

References will also be very useful when we want to talk about functions. Often, you want to provide a reference to a variable as an argument, rather than copying the value of the variable (especially if the variable contains a lot of data, and copying it would be needlessly time-consuming.)

References are declared by putting an & after the type name and before the variable. Since a reference points to an existing memory location, changing the reference or changing the memory location using its original both do the exact same thing, i.e., changing one changes the other: 

#include <iostream>
int main() {
    int x{5};
    int &r = x;
    r = 1729;
    std::cout << x << ' ' << r << "\n"; // Prints 1729 1729
    x = 42;
    std::cout << x << ' ' << r << std::endl; // Prints 42 42
    return 0;
}

A reference must be initialized when it is declared. This is an error: 

#include <iostream>
int main() {
    int x{42};
    int &y;
    y = x;
    return 0;
}

Once a reference has been initialized, it cannot be made to refer to a different memory location (reseated). For example, the following code does not make r a reference to y; it edits x to store the same value as y: 

#include <iostream>
int main() {
    int x{42}, y{1};
    int &r = x;
    r = y;
    std::cout << r << ' ' << x << ' ' << y << std::endl; // Prints 1 1 1
    return 0;
}

The whole point of a reference is to refer to a specific piece of memory. Therefore, it doesn't make any sense to create a reference to a value that's not permanently stored in memory. For example, the following code does not compile: 

#include <iostream>
int main() {
    int &r = 42; // Error
    std::cout << r << std::endl; 
    return 0;
}

It doesn't matter where you put the &, as long as it's between the type and the variable being defined. For example, the below code compiles, and r1, r2, and r3 are all references. Can you predict what it will print before you run it? 

#include <iostream>
int main() {
    int x{9};
    int& r1 = x;
    int & r2 = x; 
    int &r3 = x;
    r1 = 5;
    std::cout << x << ' ' << r1 << ' ' << r2 << ' ' << r3 << std::endl; 
    return 0;
}

The middle version (with the & floating by itself) is rarely used, and would not be considered good style. The other two are both acceptable, though the int& version would probably be most popular. This version looks like a normal declaration, where we interpret "int&" as the type "reference to int."

However, there's one situation where the "int&" version is confusing. What do you think the following code prints? 

#include <iostream>
int main() {
    int x{1}, y{2};
    int& r1 = x, r2 = y;
    r1 = 8;
    r2 = 9;
    std::cout << x << ' ' << r1 << '\n';
    std::cout << y << ' ' << r2 << std::endl; 
    return 0;
}

The first line of output is "8 8", as you probably guessed. The second line of output is "2 9", which you may not have expected. What happened is that r2 did \textbf{not} get declared as a reference, but as a regular variable. It gets initialized to the value stored in y, but since it is its own variable, when we later modify r2, that doesn't modify y. If you want r2 to also be a reference, it needs its own ampersand: 

#include <iostream>
int main() {
    int x{1}, y{2};
    int &r1 = x, &r2 = y;
    r1 = 8;
    r2 = 9;
    std::cout << x << ' ' << r1 << '\n';      // Prints 8 8
    std::cout << y << ' ' << r2 << std::endl; // Prints 9 9
    return 0;
}

It is often considered best style for each reference to be declared on its own line, to dodge this issue entirely.

const references

You can also declare a variable to be a const reference. You might wonder what this means -- I already told you that references can't be reseated, so aren't they all constant? Since we don't need the const keyword to prevent a reference from being reseated, C++ uses it to mean something else. Declaring a reference as const means that the reference cannot be used to modify the memory it points to. For example, the following code does not compile: 

int main() {
    int x{5};
    const int &r = x;
    r = 1729; // Error
    return 0;
}

In particular, if a variable is declared as const, then any reference to that variable must also be declared as const -- you can't circumvent the const by making a nonconstant reference and using that reference to modify the constant variable. C++ enforces this by preventing you from even creating a nonconstant reference to a constant variable. The following code does not compile: 

int main() {
    const int x{5};
    int &r = x;
    return 0;
}

However, you can go in the other direction; you can create a constant reference to a nonconstant variable, because that can't be used to break any rules. Declaring the reference constant promises only that this reference won't be used to modify the memory it refers to; you can still modify the memory by modifying the original variable. In particular, the value referred to be a const reference is not necessarily constant! 

#include <iostream>
int main() {
    int x{1};
    const int& r = x;
    x = 8;
    std::cout << r << ' ' << x << std::endl; // Prints 8 8
    return 0;
}

If we write the exact same code, but try to use r to change the value in memory, it's an error: 

#include <iostream>
int main() {
    int x{1};
    const int& r = x;
    r = 8; // Error
    std::cout << r << ' ' << x << std::endl;
    return 0;
}

Range-based loops

Before we talk about functions, we'll first see one more thing that we can do with references. Recall that in Python, you could loop over a list of numbers using for num in nums:. C++ provides a similar syntax: 

#include <iostream>
#include <vector>

int main() {
    std::vector<int> nums{1, 1, 2, 3, 5, 8};

    for (int num : nums) {
        std::cout << num << '\n';
    }
}

The syntax for (int num : nums) acts exactly like that Python code; it creates a variable nums, and then loops, copying each entry of nums into num in turn.

There's one potential drawback with this syntax, however. What if we didn't want to copy each entry in the vector? In the above example, the copying wasn't a problem, because ints are small, so copying them doesn't waste much time or memory. But what if we had a vector filled with data that we don't want to copy unnecessarily? Instead of copying the data itself, we can have the loop produce a reference to the existing data instead: 

#include <iostream>
#include <vector>
#include <string>

int main() {
    std::vector<std::string> presidents{"Washington", "Adams", "Jefferson", "Madison"};

    for (std::string& president : presidents) {
        std::cout << president << '\n';
    }
}

Another potential benefit of using references to the original data is that we can modify the original data. Without references, we would have been modifying the copy created by the loop rather than modifying the permanent data. 

#include <iostream>
#include <vector>

int main() {
    std::vector<double> distances{2.5, 1.8, 3.1}; // in miles

    // convert distances to km
    for (double& d : distances) {
        d *= 1.60934;
    }

    // Confirm that the data is changed:
    for (double& d : distances) {
        std::cout << d << '\n';
    }
}

On the other hand, you may not want your loop to be able to modify the original data. In that case, you can use a const reference to communicate this intention, and ensure that the data isn't accidentally modified: 

#include <iostream>
#include <vector>
#include <string>

int main() {
    std::vector<std::string> presidents{"Washington", "Adams", "Jefferson", "Madison"};

    for (const std::string& president : presidents) {
        if (president.size() > 8) {
            president = president.substr(0, 5) + "..."; // Illegal; tries to modify const reference
        } 
        std::cout << president << '\n';
    }
}

If you remove the const above, then the code compiles, and modifies the contents of the vector. If you want to modify the contents of the vector, that's fine! If not, you should keep the const to avoid accidents. This pattern of using a const reference in a range-based loop is very common, since it provides the speed of references and the safety of const.

Also, this is a good place to use the auto keyword. The compiler can figure out the type of the loop variable, because it knows what type is stored in the vector you're iterating over. Thus, const auto& is the standard pattern in range-based for loops. 

#include <iostream>
#include <vector>
#include <string>

int main() {
    std::vector<std::string> presidents{"Washington", "Adams", "Jefferson", "Madison"};

    for (const auto& president : presidents) {
        if (president.size() > 8) {
            std::cout << president.substr(0, 5) + "...\n";
        } else {
            std::cout << president << '\n';
        }
    }
}

Basics of Functions

We've already seen a little bit about how to define a function in C++, since we need to have a main() function if we want our program to run. We learned from that example that a C++ function needs to declare what type it's going to return, by writing the return type before the name of the function. For example, if we wanted to define a function that takes no arguments and always returns pi, we would declare that our function returns a double: 

#include <iostream>

double pi() {
    return 3.1415926535897932;
}

int main() {
    std::cout << pi() << " = 180 degrees\n";
    std::cout << 2 * pi() << " = 360 degrees" << std::endl;
    return 0;
}

(Of course, this is oversimpified to focus on the point of the lesson; In a real program it would be very silly to define pi as a function rather than a constant variable.)

When declaring your function, after the type and the name of the function, you put all of the arguments to the function in parentheses. (More about the syntax for that later.) With main() and our silly pi() example, there are no arguments, but we still need the parentheses to make clear that this is a function. Similarly, when we want to execute the function, we need to include the parentheses even if there are no arguments; the parentheses tell C++ that we want to execute the function, not just refer to the function by name.

For example, the below code asks C++ to print the function pi itself, rather than the value returned by calling the function. This is a strange thing to ask -- what does it even mean to print a function? The behavior may depend on your compiler. On my computer, running this code prints "1", which is probably not what you intend if you write something like this. 

#include <iostream>

double pi() {
    return 3.1415926535897932;
}

int main() {
    std::cout << pi << std::endl;
    return 0;
}

void

I mentioned above that every function has to declare its return type. What about functions that don't return anything? They can be declared as void: 

#include <iostream>
#include <string>

void hello(std::string name) {
    std::cout << "Hello, " << name << "!" << std::endl;
}

int main() {
    std::string name;
    std::cout << "What's your name? ";
    std::getline(std::cin, name);
    hello(name);
    return 0;
}

The whole point of a void function is that it doesn't return anything, so unlike other functions, it's not required to have a return statement. However, it is legal to have a return statement, with nothing following return (except the semicolon, of course). This can be useful if you want to return from your function before reaching the end of the code, similar to a break in a loop.

Function arguments

Of course, when we declare a function, we can also allow that function to take arguments. Declare the arguments inside the function's parentheses. As usual, when we declare the arguments, we also need to declare their types: 

#include <iostream>
#include <string>

void echo(std::string word, int num) {
    for (int i = 0; i < num; ++i) {
        std::cout << word;
    }
    std::cout << std::endl;
}

int main() {
    echo("Hello", 5);
    return 0;
}

As with range-based loops, the default behavior when a value is passed as an argument to a function is to create a copy of that value; if we want to avoid the overhead of copying, we can instead pass a reference. You can also pass a reference if you want your function to be able to modify the variable. Of course, you can also pass a const reference if you do not want your function to be able to modify the original variable. Once again, using const references is the standard way to get the efficiency of references and the safety of const.

But here's an example where you want your function to modify its argument: a function which converts a string to all-lowercase (leaving any non-letters alone): 

#include <iostream>
#include <string>

void lower(std::string& s) {
    for (int i = 0; i < s.size(); ++i) {
        char c = s[i];
        if ('A' <= c && c <= 'Z') {
            s[i] = static_cast<char>(c - 'A' + 'a');
        }
    }
}

int main() {
    std::string s{"This String Is Capitalized"};
    lower(s);
    std::cout << s << std::endl;
    return 0;
}

Note that if you remove the ampersand, then the lower() function does nothing; it makes changes to its temporary copy of the string, which is forgotten as soon as the function returns.

If you call a function by passing in copies of its arguments, that is "call by value" (or "pass by value"). If you call a function by passing referenes to its arguments, that is "call by reference."

Default arguments

You can provide default arguments for your functions in C++, very similar to how you did that in Python. When you declare an argument, you can follow it with an equals sign, and then your desired default value. In other words, it's the usual syntax to assign a value to a variable. When somebody calls your function, if they provide a value for the variable, that value is used; otherwise, the default value is used. For example, we can modify our hello function from earlier, so that it refers to the user as "user" if a name is not provided: 

#include <iostream>
#include <string>

void hello(std::string name = "user") {
    std::cout << "Hello, " << name << "!" << std::endl;
}

int main() {
    hello("James"); // prints "Hello, James!"
    hello();        // prints "Hello, user!"
    return 0;
}

When a function with default arguments is called, C++ fills in the provided arguments from left to right. After that, any remaining arguments use their default values. 

#include <iostream>

int f(int x, int y = 3, int z = 2) {
    return x * y + z;
}

int main() {
    std::cout << f(5) << std::endl; // Equivalent to f(5, 3, 2)
    std::cout << f(1, 7) << std::endl; // Equivalent to f(1, 7, 2)
    return 0;
}

You may choose to provide default values for none, some, or all of the arguments to a function. As a result of the left-to-right rule, all arguments without default values must appear before all arguments with default values. (Why wouldn't it make sense to do otherwise?) 

#include <iostream>

int f(int x = 1, int y, int z = 2) { // Will not compile
    return x * y + z;
}

Recursion

As in Python, a C++ function can be defined recursively, i.e., by calling itself. You should already know that a recursive function must have a base case (an argument for which the function can be executed without calling itself) to avoid going into an infinite loop.

For example, suppose you are interested in the sequence defined by a0 = 0 and an+1 = 3*an + 2. The starting value a0 = 0 provides a base case, and then the recurrence relation lets us calculate an for larger values of n. We can calculate an based on an-1, which we can calculate based on an-2, and so on until we reach the known value of a0. Here's a function to calculate it: 

#include <iostream>

int a(int n) {
    if (n <= 0) {
        return 0;
    }
    return 3 * a(n-1) + 2;
}

int main() {
    int n;
    std::cout << "Enter n: ";
    std::cin >> n;
    std::cout << "a_n = " << a(n) << std::endl;
    return 0;
}

Aside: We could write this more compactly using the C++ conditional operator, which has the form condition ? expression_if_true : expression_if_false. This can be used as a more compact alternative to if-else, if you simply want to get one of two values depending on a condition. 

#include <iostream>

int a(int n) {
    return n <= 0 ? 0 : 3 * a(n-1) + 2;
}

int main() {
    int n;
    std::cout << "Enter n: ";
    std::cin >> n;
    std::cout << "a_n = " << a(n) << std::endl;
    return 0;
}

This is probably the type of recursion you're most familiar with: we define a function a(n) whose domain is the nonnegative integers by defining a(0) and then recursively defining a(n) in terms of a of smaller values. Each step, we look at smaller and smaller values of the input, and it must inevitably reach 0, so we know that we will reach the base case and terminate.

You've probably also used recursion in similar circumstances. For example, if you're defining a function f whose argument is a string, you may be able to define it recursively by defining f("") and giving a recursion relation that relates f(s) to f of some shorter string (e.g., a substring of s). In this case, s.size() is the non-negative integer which keeps on decreasing, and must eventually reach 0 (the base case). You can do the same thing with vectors.

But you can also define recursive functions in more complicated ways. For example, the Euclidean algorithm is an efficient recursive algorithm for calculating the greatest common divisor (gcd) of two integers. The naive way to calculate the gcd of two integers is to find all the divisors of both integers, and then comparing the lists to find the greatest divisor that they have in common. This is wildly inefficient: finding all the divisors of an integer is equivalent to finding the prime factorization of that integer, which is a famously difficult problem. (In fact, much of modern encryption is based on the assumption that large numbers cannot be factored efficiently.) The Euclidean algorithm provides a much more efficient way of calculating the gcd, taking advantage of the fact that gcd(a, b) = gcd(b, a % b). (Can you prove that this algorithm always terminates?) 

#include <iostream>
#include <cmath> // Provides the absolute value function

int gcd(int a, int b) {
    return b == 0 ? std::abs(a) : gcd(b, a % b);
}

int main() {
    std::cout << gcd(1242, 60) << std::endl; // Prints 6
    return 0;
}

Note that anything that can be done with recursion can also be done with loops. In fact, loops may be technically preferable, because recursion can use up a lot of memory: if you want to use our function from earlier to calculate a(500), the computer needs to remember "I'm calculating a(500), which requires me to calculate a(499), which requires me to calculate a(498), which ..." until it gets to a(0). If we had coded this with a loop, the memory demand would be lower.

Side note: Ihe memory available to keep track of all these recursive calls is not the full memory available to your program. The recursive calls are tracked in a smaller section of memory called the stack, which we'll talk more about later. Therefore the program can't keep track of as many levels of recursion as you might expect; typically you can go a few thousand levels deep. Once you fill up all the stack memory, you get a situation called stack overflow. (You can ask the compiler to provide extra stack memory, but if you find yourself needing to do that, it's typically a band-aid solution to poorly-designed code.)

Despite this issue, we often prefer recursion because it's easier for humans to reason about; for example, our definitinon of a(n) above was a one-liner that basically just said exactly what the mathematical definition said; it took almost no thought to write. You could also write the definition using a for loop instead of recursion, but that would probably take a little more effort. Do you iterate through the loop n-1 times or n times? You might have to stop and think about that.

If you're not worried about the memory demands of recursion (for example, because you know that your function will only be called in situations that require only a few levels of recursion), then using a recursive function can be a great idea. In general, we should strive to make our programs as easy for humans to understand as possible, until a potentially-confusing optimization actually becomes necessary. Recursion is often the easiest way to define a function.

There's another solution to this memory issue, which we'll discuss in the section after the following exercises.

Optimization

Anything that can be done with recursion can, in theory, be done with a loop. We mentioned above that one solution if your recursion depth is large enough to cause stack overflow is to rework the code to use a loop instead of recursion. But there's sometimes another solution: just use recursion, and let the compiler fix it for you!

When you compile your code, many compilers will automatically optimize the code for you, to make it run more efficiently. If a recursive function has a particularly simple form, and the compiler is configured to optimize aggressively, then the compiler may be able to figure out how to turn the recursion into a loop for you! However, this behavior is not guaranteed by the C++ standard, so to be safe, you shouldn't rely on it; some compilers might not do the optimization for you.

For example, consider the below function which computes the nth triangular number, defined by Tn = 1 + 2 + ... + n: 

#include <iostream>

int t(int n) {
    if (n == 0) {
        return 0;
    }
    return n + t(n - 1); 
}

int main() {
    std::cout << t(9000) << std::endl;
    return 0;
}

Save this in a file triangular.cpp, and try compiling it using the terminal command 

g++ -o triangular -O1 triangular.cpp

When you go to run the program, it probably won't work. Now compile it again, using: 

g++ -o triangular -O2 triangular.cpp

This time, it probably worked! What happened?

The -O option tells the compiler how aggressively to optimiize. You can use -O1, -O2, and -O3, with higher numbers corresponding to more aggressive optimization. (There are other options also, but we won't worry about them.) When we compiled using the option -O1, the compiler didn't optimize away the recursion, and we got a stack overflow when we ran the program.

If you want to take advantage of this sort of compiler optimization, you may want to look up the term tail-recursive; a tail-recursive function is easiest to turn into a loop, so that gives you the highest chance that the compiler will do it for you. But it generally takes some extra work to put a function into tail-recursive form, at which point you might as well just rewrite it using a loop so that you don't need to count on the compiler to provide an optimization that isn't promised by the C++ standard.

Forward declaration

In C++, a function must always be declared before any code that calls it. For example, the below is illegal: 

#include <iostream>

void print_an(int n) {
    std::cout << a(n) << '\n';
}

int a(int n) {
    return n <= 0 ? 0 : 3 * a(n-1) + 2;
}

int main() {
    int n;
    std::cout << "Enter n: ";
    print_an(n);
    return 0;
}

We can fix this by swapping the order in which we declare the two functions, so that a(n) is defined before print_an() tries to use it.

However, we can't work around the issue that easily in the case of mutual recursion, in which two functions both call each other. If f calls g and g calls f, then whichever one we define first will come before the definition of the other, which seems like it violates the rule above.

But actually, I only said that a function needs to be declared before it's used, not that it needs to be defined. Much like variables, functions can be declared in C++ without defining them. This is called forward declaration. The following example of mutual recursion illustrates its use. (The example itself is extremely silly: this is a ridiculous way to determine whether a number is even or odd. But mutual recursion doesn't become genuinely helpful until you start getting into much more complicated situations, which would be too messy for the sake of an introductory example.) 

#include <iostream>

bool isOdd(unsigned int n); // Forward declaration so isEven can use isOdd

bool isEven(unsigned int n) {
    return n == 0 ? true : isOdd(n - 1);
}

bool isOdd(unsigned int n) {
    return n == 0 ? false : isEven(n - 1);
}

int main() {
    std::cout << std::boolalpha; // Print bools as text
    std::cout << isEven(123) << std::endl; // Prints false
    return 0;
}

There are other reasons why you might want to declare a function without defining it, but we won't worry about them for now.

One potentially confusing thing about forward declaration: if you want to give a forward declaration of a function with default arguments, you need to give the default arguments in the forward declaration and not in the actual definition. The following code is wrong: 

#include <iostream>
#include <string>

void hello(std::string name = "user");

int main() {
    hello("James"); // prints "Hello, James!"
    hello();        // prints "Hello, user!"
    return 0;
}

void hello(std::string name = "user") {
    std::cout << "Hello, " << name << "!" << std::endl;
}

If we remove the second mention of the default argument, then the code works as expected: 

#include <iostream>
#include <string>

void hello(std::string name = "user");

int main() {
    hello("James"); // prints "Hello, James!"
    hello();        // prints "Hello, user!"
    return 0;
}

void hello(std::string name) {
    std::cout << "Hello, " << name << "!" << std::endl;
}
