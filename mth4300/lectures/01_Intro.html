Lecture 01: Introduction to C++

Getting Started

If you haven't already read my Getting Started document and followed the instructions there, you should do that when you get the chance. For now, you can get through this lecture without having completed all the tasks there.

Hello, World

The below is the Hello World program that was used as the example program in Getting Started. 
#include <iostream>
int main() {
    std::cout << "Hello, world!" << std::endl;
    return 0;
}

We'll use it as our first example as we start to discuss how C++ works. Note that you can copy this code (and any other code appearing in these notes) by clicking the button on the right.

The C++ Compiler

As you've already seen if you read through Getting Started, C++ is a compiled language, which means that a program called a compiler needs to convert the human-readable source code into instructions that the computer can execute. We'll be able to say more about this process later, once you know more about C++.

For now, there's only one detail you need to know: the source is first handled by a preprocessor, which does not know any C++ syntax, but simply performs text replacements indicated by preprocessor directives, which are lines that start with #. In the Hello World example, the preprocessor directive "#include <iostream>" tells the preprocessor to replace this line with the contents of the iostream file, which contains code for input and output.

Statements

A single instruction in C++ is called a statement. Every statement is required to end with a semicolon. Note that preprocessor directives are not considered statements, so "#include <iostream>" must not end with a semicolon.

Whitespace and Braces

Unlike Python, C++ is not a whitespace-sensitive language. This is one reason why statements need to end in semicolons: C++ doesn't treat newlines differently than spaces, so we need some other way of indicating the end of a statement. Another consequence is that we need a different way to create blocks of code consisting of several statements; Python does this with indentation, which doesn't work in C++. Instead, C++ uses curly braces to create blocks of code. In the Hello World example above, the function main() consists of several statements. We tell C++ which statements are part of main() by enclosing them in braces.

There are several popular formatting styles for braces. My preferred style is to put the opening brace on the same line as the code that necessitated it, but some style guides call for the brace to be put on instruction own line. (I don't care what you choose, as long as you're consistent.) In most popular styles, the closing brace goes on its own line, indented to the same level as the line that opened the braces. The code inside the braces is indented.

Comments

C++ provides two ways to write comments in your code. A single-line comment can be started with //; everything on that line after the // is ignored. A multi-line comment starts with /* and ends with */. In either case, the entire comment is replaced by a single whitespace character before preprocessing. 

#include <iostream>
/* This is a very boring program which exists
   only to illustrate comments in C++. */
int main() {
    std::cout << "This will print" << std::endl; // This is a comment
    // std::cout << "This won't print because this whole line is a comment" << std::endl;
    return 0;
}

main()

When a C++ program is launched, it automatically executes the code in the main() function. The declaration "int main()" says that the main function must return an integer. This serves as a status code for the operating system; 0 indicates success, and anything else indicates failure. Different types of failures can return different non-zero numbers, to help with troubleshooting.

As you can see above, main() usually ends with "return 0;". Strictly speaking, this isn't necessary -- the compiler will automatically insert a "return 0;" at the end of main() if you don't write it. (This only happens with main(). Any other function that returns a value must return a value explicitly.) Nonetheless, many style guides suggest that you write the "return 0;" anyway.

Variable Declaration and Initialization

In C++, all variables must be explicitly declared before they can be used. For example, the below code is incorrect: 

#include <iostream>
int main() {
    a = "Hello, world!";
    std::cout << a << std::endl;
    return 0;
}

If you run it, you will see: "error: 'a' was not declared in this scope".

This is because C++ requires you to declare the variable by telling C++ the type of the variable. (Actually, that's not quite true, as we'll see below.) We can correct the above code by telling C++ that the variable is a string: 

#include <iostream>
int main() {
    std::string a = "Hello, world!";
    std::cout << a << std::endl;
    return 0;
}

Aside: The "std" in "std::string" and "std::cout" stands for "standard"; this code is provided as part of the C++ standard library. To get access to the string type, you can use "#include <string>". We didn't need to do so explicitly above, because iostream already includes string.

When we write a statement like "int a = 5;", that actually tells C++ to do two separate things: first set aside memory to store an int, and then store the value 5 in that memory. In fact, C++ allows us to perform those two operations separately; we can set aside memory by declaring the variable without the variable by assigning a value: 

#include <iostream>
int main() {
    int a;
    a = 42;
    std::cout << a << std::endl;
    return 0;
}

Do not try to access the value of an uninitialized variable! That results in undefined behavior. Depending on the compiler, this may cause the program to crash, to use a garbage value (i.e., whatever was already in memory when that section of memory was claimed by the variable), or to use a default value (such as 0 for an int). For example, with the compiler on my computer, the code below prints 0: 

#include <iostream>
int main() {
    int a;
    std::cout << a << std::endl;
    return 0;
}

Note also that you can declare several variables (of the same type) at once, and you may initialize some (or all) of them simultaneously. For example, the below is valid code (which prints "15"): 

#include <iostream>
int main() {
    int a, b;
    int c = 3, d, e = 5;
    a = 1;
    b = 2;
    d = 4;
    std::cout << a+b+c+d+e << std::endl;
    return 0;
}

Modern C++ provides another option for declaration: the auto keyword. Instead of writing the type in the declaration, you can write "auto" instead, and the compiler will automatically determine the type of the variable based on the value that you use to initialize it. (Of course, that means that auto is only an option if you declare and initialize simultaneously.) For example, in the below code, the compiler can determine automatically that n should be an int: 

#include <iostream>
int main() {
    auto a = 42;
    std::cout << a << std::endl;
    return 0;
}

Using "auto" provides some advantages:

  • Some types have complicated names that can unpleasant (or even impossible) to write out. Letting auto determine the type for you makes code easier to write and read.
  • It avoids implicit conversions. If you write a declaration where the initialization value on the right doesn't have the type declared on the left, C++ will try to automatically convert to the type you wrote. Thus, if you write the wrong type, the program may perform a conversion which leads to unexpected behavior, rather than crashing and revealing your mistake.
  • Using auto makes it easier to later change the types used in your program. For example, if you write a program using ints, but later realize that you need to work with numbers larger than the maximum int, you'll need to update every declaration that mentions "int". If you used auto, you won't need to make as many changes.

But it also has some disadvantages:

  • Sometimes, it can make code harder to read, because the reader can't tell at a glance what the types of variables are. (This can be mitigated if your IDE provides type information.)
  • It can make code harder to debug. An explicit type declaration means that the compiler notices immediately if a variable is initialized with a type that the programmer didn't expect, whereas auto allows the mistake to happen. The program may still fail to compile if the unexpected type causes a problem later, but then the error message will point to that later code rather than the actual mistake.

Modern C++ style is to prefer using auto, unless you have a reason to declare a type explicitly. But for most in-class examples and test problems in this course, I'll generally avoid auto, so that it's easier for you to quickly see what's going on when you read a new example/problem.

Brace Initialization

Modern C++ provides another way to initialize variables, by putting the desired value inside curly braces instead of using an equals sign: 

#include <iostream>
int main() {
    double pi{3.14}; // Does the same thing as "double pi = 3.14;"
    std::cout << pi << std::endl;
    return 0;
}

This is now considered the preferred way to initialize variables. One reason is that it prevents narrowing conversions, in which data is lost when one type is converted to another. For example, what do you think the below code will print? 

#include <iostream>
int main() {
    int x = 4.8; 
    std::cout << x << std::endl;
    return 0;
}

This prints 4, because C++ rounds down when trying to store a non-integer value in an int. But that can be confusing, so we probably don't want such rounding to happen unless the code explicitly says it should. If we use brace initialization, we won't get this silent rounding behavior. In fact, the below code doesn't compile: 

#include <iostream>
int main() {
    int x{4.8}; 
    std::cout << x << std::endl;
    return 0;
}

We'll see later how you could explicitly ask C++ to round 4.8 down to an int, if necessary.
