Lecture 10: Operator Overloading

So far, we've added a bunch of technical memory-management methods to our Polynomial class, but we haven't added most of the operations that we would like to be able to do with polynomials, such as addition, subtraction, and multiplication. There's a reason for that.

Suppose you have three Polynomials, f, g, and h, and you want to calculate f * g + h. If you were going to do that with material that we've covered so far, you might define methods Polynomial::add and Polynomial::multipliy and then write something like f.multiply(g).add(h). But that's annoying to type and hard to read: we would like to be able to write f * g + h in our code. That's where operator overloading comes in.

Recall that overloading refers to the idea that we can have multiple functions with the same name, distinguished by the types of their arguments. Well, addition is a function, so we can overload it too. (We sometimes don't think of it as a function because we write things like "a+b" instead of "+(a, b)," but it is a function: it accepts two arguments and returns a result.) In particular, if we define a version of the addition operator that accepts two Polynomial objects as arguments, then we'll be able to use + to add Polynomial objects.

We've already seen an example of operator overloading: the copy assignment operator and move assignment operators both overload the operator =. Recall that the way we accomplished that was by defining a function operator= as a member function within our class. We'll overload other operators in basically the same way: name the function operator plus the symbol that you're trying to overload.

We'll continue using Polynomial for the examples in this lecture. For your convenience, the code is provided below (and consolidated into one file) for you to copy: 

// polynomial.h: 
#pragma once

#include <vector>

class Polynomial {
public:
    Polynomial(const std::vector<int>& coefficients);
    Polynomial(const Polynomial& other);
    Polynomial(Polynomial&& other) noexcept;
    ~Polynomial();
    Polynomial& operator=(const Polynomial& other);
    Polynomial& operator=(Polynomial&& other) noexcept;
    int eval(int n) const;
private:
    int degree_;
    int* coefficients_;
};

// polynomial.cpp:

#include <vector>
#include <numeric>
//#include "polynomial.h" // Not used in the in-class version which puts everything in one file

// Copy the given coefficients vector into coefficients_, while also removing 
// any leading zeros so that degree_ is calculated correctly.
Polynomial::Polynomial(const std::vector<int>& coefficients) {
    int i;
    for (i=0; i < coefficients.size(); ++i) {
        if (coefficients[i] != 0) {
            break;
        }
    }
    degree_ = coefficients.size() - i - 1;
    coefficients_ = new int[degree_ + 1];
    for (int j = i; j < coefficients.size(); ++j) {
        coefficients_[j-i] = coefficients[j];
    }
}

// Copy constructor
Polynomial::Polynomial(const Polynomial& other)
    : degree_(other.degree_), coefficients_(new int[degree_ + 1]) {
    std::copy(other.coefficients_, other.coefficients_ + degree_ + 1, coefficients_);
}

// Move constructor
Polynomial::Polynomial(Polynomial&& other) noexcept
    : degree_(other.degree_), coefficients_(other.coefficients_) {
    other.degree_ = -1; 
    other.coefficients_ = nullptr;
}

Polynomial::~Polynomial() {
    delete[] coefficients_;
}

// Copy assignment operator
Polynomial& Polynomial::operator=(const Polynomial& other) {
    if (this == &other) {return *this;}
    delete[] coefficients_;
    degree_ = other.degree_;
    coefficients_ = new int[degree_ + 1];
    std::copy(other.coefficients_, other.coefficients_ + degree_ + 1, coefficients_);
    return *this;
}

// Move assignment operator
Polynomial& Polynomial::operator=(Polynomial&& other) noexcept {
    if (this == &other) return *this;
    delete[] coefficients_;
    degree_ = other.degree_;
    coefficients_ = other.coefficients_;
    other.degree_ = -1;
    other.coefficients_ = nullptr;
    return *this;
}

int Polynomial::eval(int n) const {
    auto f = [n](int acc, int val) { return acc * n + val; };
    return std::accumulate(coefficients_, coefficients_ + degree_ + 1, 0, f);
}

How to overload operators

Before we start overloading some more operators, there's one more technicality that we need to discuss: where do we define our overloaded operators?

For example, we've seen that when you overload the assignment operator, you define the function as a member function of your class, e.g., Polynomial::operator=. Specifically, when you overload an operator, the overloaded operator is defined as a member function of the left argument, e.g., when we were overloading f = g by defining Polynomial::operator=(Polynomial&& other), f was the object pointed to by this, and g was other.

But for some operators, this wouldn't make sense. Suppose you tried to overload the << operator, so that you could write code like std::cout << f and print your polynomial to standard output. Since std::cout is the left argument, if we tried to define operator<< as a member function of a class, it would need to be a member of std::cout's class (which is std::ostream). Of course, you can't modify the code for std::ostream, so this is impossible.

Unfortunately, things now get a little complicated: some overloaded operators must be member functions, some must be non-member functions, and some can be defined either way (though there are style guidelines that you should prefer one or the other). Specifically:

  • Must be a member function: = (assignment), [] (subscript), () (function call), -> (member access).
  • Should be a member function: Operators that are bound tightly to a single object, such as unary operators such as ! and ++ and compound assignment operators such as +=. (Note that you must overload += separately even if you already overloaded +. In fact, it's recommended that you overload += first and then use it to define +.)
  • Should be a non-member function: Symmetric binary operators, such as +, -, *.
  • Must be a non-member function: Stream I/O operations (<< and >>), and other operators where your class is not the left argument.

friend

The discussion in the previous section raises a new problem. For example, we said that we wanted to overload the + operator using a non-member function. But how are we going to do that? Calculating the sum of two polynomials requires us to know their coefficients, but the coefficients_ array is private, so a non-member function can't access it. (In theory, we could solve this by making the implementation details public, but we don't want to do that -- remember that we had good reasons for keeping them private.)

The answer is that we can declare a non-member function as a friend of our class: a friend function has access to the private attributes of the class, as if it were a member function. Basically, you declare the function in the public section of the class as if it were a member function, but with the keyword friend at the beginning. We'll see an example soon, but first lets add one new feature to our Polynomial class.

Overloading the subscript operator

Currently, coefficients_ is private. But it's not hard to imagine situations where a user might want to access a specific coefficient, either to read the value or to edit it. Let's overload the subscript operator, so that the coefficient of xn in f is given by f[n].

Aside: Is this actually a good idea? Or should we define something like f.coefficient(n) instead? You might notice that f[n] looks a lot like f(n), so this notation could potentially cause more confusion than it's worth. In the real world, we might well decide that the benefit of f[n] being easier to type is outweighed by the drawback of being harder to read; after all, professional programmers spend much more time reading code than writing it. But for this in-class example, we want to see how to overload the subscript operator, so we'll just do it and not worry about whether it's a good idea.

In polynomial.h, add two new declarations: 

int& operator[](size_t i);
const int& operator[](size_t i) const;

We have a const and a non-const version of the operator. The non-const version returns a reference, so that it can be used as an lvalue. For example, f[2] = 3 will change the x2 coefficient of f to 3 (assuming that f has degree at least 2, so that there is an x2 coefficient to change). But then that can't be used with a const Polynomial, so we also need a version that returns a constant reference to cover that case. This technique of writing two overloads of operator[] is the standard way of doing it.

Now add the following definitions to polynomial.cpp: 

int& Polynomial::operator[](size_t i) {
    return coefficients_[degree_ - i];
}
const int& Polynomial::operator[](size_t i) const {
    return coefficients_[degree_ - i];
}

Remember that coefficients_ stored the coefficients in reverse order, hence the need for degree_ - i above.

Notice that we do not perform any bounds-checking when using operator[]. This is fairly traditional, to be consistent with the behavior of the standard library containers. Of course, you can add bounds checking if you prefer (and there are situations where that might be appropriate). If operator[] is not bounds-checked, then it's also fairly standard to add a .at() method that is bounds-checked (again, just like the standard containers).

But in our case, .at() is not a great name; let's call it .coefficient() instead. Also, instead of throwing an exception on out-of-bounds access, let's simply return 0 instead. After all, a general-purpose container like std::vector, can't really do anything sensible when faced with an out-of-bounds index, but there is a sensible behavior for Polynomial: if you're asked for the x-1 or x9 coefficient of a degree-8 polynomial, you can simply say that they're 0.

Add the following declaration to polynomial.h: 

int coefficient(int i) const;

Add the following definition to polynomial.cpp: 

int Polynomial::coefficient(int i) const {
    return (i < 0 || i > degree_) ? 0 : coefficients_[degree_ - i];
}

Note that this time, we decided not to return a reference; since we allowed out-of-bounds indices, it wouldn't make any sense to return a reference. Also, we allowed the argument to be an int rather than an unsigned type; we're performing bounds-checking anyway, so there's no harm in allowing negative arguments.

Next, we'll define polynomial addition. This method will make it a little easier to do so, since we won't need to manually check bounds.

Overloading the addition operators

Now we're ready to define addition of polynomials. As mentioned above, it's good form to start by overloading the += operator. We'll need the std::max function in order to do that, so add #include <algorithm> at the top of your polynomial.cpp.

Now add the following public declaration in polynomial.h: 

Polynomial& operator+=(const Polynomial& other);

And add the following definition in polynomial.cpp: 

Polynomial& Polynomial::operator+=(const Polynomial& other) {
    int newDegree = std::max(this->degree_, other.degree_);
    while (newDegree > -1 && this->coefficient(newDegree) + other.coefficient(newDegree) == 0) {
        --newDegree;
    }
    int* newCoefficients = new int[newDegree + 1];
    for (int i = 0; i <= newDegree; ++i) {
        newCoefficients[newDegree - i] = this->coefficient(i) + other.coefficient(i);
    }
    delete[] coefficients_;
    coefficients_ = newCoefficients;
    degree_ = newDegree;
    return *this;
}

The declaration should be largely as you expect. As mentioned above, we overload += as a member function. Of course, we pass other as a constant reference, because we don't want to make an unnecessary copy of other, but we also don't want to modify it. Notice that we return this*; as we saw with the assignment operator, this supports operator chaining.

We haven't mentioned this before, but the += operator can be chained: you can write a += b += c to mean "First add c to b, and then add the new value of b to a." You should never do this: it's much clearer to simply write b += c; a += b; as two separate lines. But your overloaded += should support it correctly even though it's generally bad style.

Now, define operator+. First, add this as a public declaration in polynomial.h: 

friend Polynomial operator+(Polynomial f, const Polynomial g);

And add the definition to polynomial.cpp: 

Polynomial operator+(Polynomial f, const Polynomial& g) {
    f += g; 
    return f;
}

This definition might look a little funny at first, but notice that f is being passed by value. Therefore f += g modifies the copy of f, while the original f is (correctly) left alone.

Overloading some more arithmetic operators

Now that we've overloaded the addition operator, we can overload subtraction and multiplication in the same way. Naturally, the code for overloading subtraction looks extremely similar to the code for overloading addition, while the code for polynomial multiplication is a little more complicated.

Add the following declarations to polynomial.h: 

Polynomial& operator-=(const Polynomial& other);
friend Polynomial operator-(Polynomial f, Polynomial const& g);
Polynomial& operator*=(const Polynomial& other);
friend Polynomial operator*(Polynomial f, Polynomial const& g);

Add the following definitions to polynomial.cpp: 

Polynomial& Polynomial::operator-=(const Polynomial& other) {
    int newDegree = std::max(this->degree_, other.degree_);
    while (newDegree > -1 && this->coefficient(newDegree) - other.coefficient(newDegree) == 0) {
        --newDegree;
    }
    int* newCoefficients = new int[newDegree + 1];
    for (int i = 0; i <= newDegree; ++i) {
        newCoefficients[newDegree - i] = this->coefficient(i) - other.coefficient(i);
    }
    delete[] coefficients_;
    coefficients_ = newCoefficients;
    degree_ = newDegree;
    return *this;
}

Polynomial operator-(Polynomial f, const Polynomial& g) {
    f -= g; 
    return f;
}

Polynomial& Polynomial::operator*=(const Polynomial& other) {
    int newDegree = this->degree_ + other.degree_;
    int* newCoefficients = new int[newDegree + 1]();
    for (int i = 0; i <= newDegree; ++i) {
        newCoefficients[degree_ - i] = 0; // coefficient of x^i
        for (int k = 0; k <= i; ++k) {
            newCoefficients[degree_ - i] += this->coefficient(k) * other.coefficient(i - k);
        }
    }
    delete[] coefficients_;
    coefficients_ = newCoefficients;
    degree_ = newDegree;
    return *this;
}

Polynomial operator*(Polynomial f, const Polynomial& g) {
    f *= g; 
    return f;
}

Overloading ==

Another natural thing that we'd like to be able to do with polynomials is check whether two polynomials are equal. To be able to do that, we need to override the == operator.

Prior to C++20, it was considered best practice to make operator== a non-member function; since C++20, it is considered best to make it a member function. In this course, I'll make it a non-member function so that we don't need to specify the version of C++ that we're using when we compile; in your own code, you can do whatever you prefer.

Usually, you'll want == to have the default behavior, which is to return true if all the member attributes of the objects being compared are the same. In C++20 (or later), you can tell C++ to do this using the default keyword. (The default keyword is also useful to tell C++ to create a default constructor -- remember that C++ doesn't automatically create a default constructor if you have defined any constructor of your own.) Specifically, you would write: 

bool operator==(const Polynomial& other) const = default;

However, this would not result in the correct behavior for our Polynomial class, so we could not use default in this case. Can you see why?

Here's the older style, which is what we'll add to our code: 

// In polynomial.h: 
friend bool operator==(const Polynomial& f, const Polynomial& g);

// In polynomial.cpp:
bool operator==(const Polynomial& f, const Polynomial& g) {
    if (f.degree_ != g.degree_) {return false;}
    for (int i = 0; i <= f.degree_; ++i) {
        if (f.coefficients_[i] != g.coefficients_[i]) {return false;}
    }
    return true;
}

Now we can test our code more easily. For example, if we want to test that multiplication works correctly, we can run the following code: 

Polynomial f({2, -5}), g({1, 3, 4}), h({2, 1, -7, -20});
std::cout << std::boolalpha << (h == f * g) << std::endl;

This prints true, because (2x-5)(x2 + 3x + 4) = 2x3 + x2 - 7x - 20.

Overloading <<

We would like to be able to print a Polynomial conveniently, so next we'll overload the << operator. (It's also possible to overload the >> operator, but we won't bother with that for our Polynomial class; being able to consistently translate naturally-written user input into a Polynomial object would be fairly tricky.)

To be able to print objects in our class, we need to overload operator<<. The object that goes on the left side of the << operator has type std::ostream. (You'll need to add #include <ostream> in the header file to get access to std::ostream.) Recall that the << operator returns a reference to the std::ostream to support chaining. Therefore the declaration in polynomial.h should look like this: 

friend std::ostream& operator<<(std::ostream& os, const Polynomial& f);

The definition in polynomial.cpp will look like: 

std::ostream& operator<<(std::ostream& os, const Polynomial& f) {
    if (f.degree_ == -1) { // Print the 0 polynomial correctly
        os << '0';  
        return os;
    }
    for (int d = f.degree_; d >= 0; --d) {
        int coeff = f.coefficient(d);
        if (coeff == 0) {continue;}
        // Print coefficient
        if (d == f.degree_) {
            if (coeff == 1) {
                if (d == 0) {os << '1';} 
            } else if (coeff == -1) {
                os << (d == 0 ? "-1" : "-");
            } else {
                os << coeff;
            }
        } else {
            os << (coeff > 0 ? " + " : " - ");
            if ((coeff != 1 && coeff != -1) || d == 0) {os << std::abs(coeff);} 
        }
        // Print power of x
        if (d == 1) {
            os << 'x';
        } else if (d > 1) {
            os << "x^" << d;
        }
    }
    return os;
}

Printing a nicely-formatted polynomial is a little bit tricky, because there are lots of edge cases to consider. We need to handle negative coefficients nicely, by printing them as subtraction rather than as adding a negative. E.g., we print things like "4x^2 - 1" rather than "4x^2 + -1". But then the handling of negative coefficients needs a special case for the leading term, so that we don't turn "-5x^2" into "- 5x^2". We need to be careful not to print zero coefficients, so that we don't print things like "4x^2 + 0x - 1". But then the zero polynomial needs its own special handling, so that it doesn't print as an empty string. We also need to simplify the degree-0 and degree-1 terms, so that we get "5x + 3" rather than "5x^1 + 3x^0". We need special handling for coefficients of 1 and -1, so that we don't print things like "1x^3 - 1x^2"; that special handling needs its own special handling, so that we do print the "1" if it's the constant term.

It's a good exercise to read through this code on your own time and try to understand why it's designed the way it is. But the point of this lesson isn't about how to convert a polynomial to a string; it's about how to overload the << operator. That part is fairly simple: we first provide the code that writes to the output stream, and then end with return os;.

Letting Polynomial handle constants

Now that we can add, subtract, and multiply polynomials using the usual operators, any code that we write with the Polynomial class will be much easier to read. But we've only defined operations between two polynomials; what if we want to be able to write something like 2 * f?

One possible solution is that we could add another overload to the multiplication operator:

friend Polynomial operator*(int c, Polynomial const& f);

But it would take a bit of work to cover all the operations, with the int on the left or the right. Fortunately, there's an easier way.

We'll add another overload to the constructor, which takes as argument an int and constructs the corresponding constant Polynomial: 

// In polynomial.h: 
Polynomial(int c);

// In polynomial.cpp:
Polynomial::Polynomial(int c) : Polynomial(std::vector<int>{c}) {}

This uses a trick that we haven't seen before. (You won't be required to remember it for this course, but you might want to -- it is a nice shortcut.) A constructor can call an already-defined constructor, using syntax similar to a member initializer list. As with a member initializer list, we could have added code in the body of the new constructor, which would run after calling the old constructor. But in this case, we didn't need to.

Now we can write things like Polynomial f(5) to declare a constant polynomial, where before we would have needed to write Polynomial f({5}). But even better, this means that the compiler now knows how to convert an int to a Polynomial, and it's smart enough to do that in situations where it expects a Polynomial but receives an int. In particular, we can now add/subtract/multiply a Polynomial and an int, without needing to define a lot of extra overrides. For example, the below code will print 20x-7: 

Polynomial f({4, -1});
std::cout << (5 * f - 2) << std::endl;

Note: What if you don't want the compiler to automatically cast operator arguments like that? For example, you might prefer that your code only compiles if the types match up correctly as-written, rather than have possible bugs hiding behind implicit conversions. You can put the explicit keyword before the constructor declaration to tell the compiler that the constructor should only be used when called explicitly. (You won't be required to know explicit for this course.)

            }
        } else {
            os << (coeff > 0 ? " + " : " - ");
            if ((coeff != 1 && coeff != -1) || d == 0) {os << std::abs(coeff);} 
        }
        // Print power of x
        if (d == 1) {
            os << 'x';
        } else if (d > 1) {
            os << "x^" << d;
        }
    }
    return os;
}

int Polynomial::eval(int n) const {
    auto f = [n](int acc, int val) { return acc * n + val; };
    return std::accumulate(coefficients_, coefficients_ + degree_ + 1, 0, f);
}

int Polynomial::coefficient(int i) const {
    return (i < 0 || i > degree_) ? 0 : coefficients_[degree_ - i];
}
