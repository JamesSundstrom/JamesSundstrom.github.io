Lecture 05: Memory and Pointers

Unlike Python, C++ sometimes requires you to think about the specifics of how data is stored in the program's memory.

Memory

A C++ program has two different sections of its memory, the stack and the heap, which serve different purposes and need to be handled in different ways. It's important to understand the differences between them.

The stack

The stack is where local variables (variables that live inside a function, such as main()) exist. The compiler knows what variables are needed and how much memory is needed to store each one, so it knows exactly how much space to allocate on the stack. When a function is finished running, its local variables are no longer needed, and they can be removed from the stack.

Indeed, that property explains why this section of memory is called the stack. In computer science, a stack is a last-in-first-out (LIFO) data structure, meaning that the last data put onto the stack is the first data removed. This is just like a real stack: if you make a stack of boxes in the real world, and then want to read its data, you had better remove the top (last-added) box first.

A LIFO order is exactly what we want when we're calling functions. Suppose your code calls a function f, which calls a function g, which calls a function h. When f gets called, its local variables are put on the stack. (The allocated memory for f is called its stack frame,) Then f calls g, so the stack frame for g is added to the stack. Then g calls h, so the stack frame for h is added to the stack. Finally, h finishes running, so its stack frame can be removed from the top of the stack, freeing that memory in case it's needed later by some other function. This returns control to g, which can finish running and remove its stack frame. Then this returns control to f, which can finish running and remove its stack frame. Note that this is LIFO, as promised: the last function called (h) was the first to have its stack frame removed.

Each variable has an address that tells the computer the exact memory location where it can be found. By convention, this address is given in hexadecimal (base 16, where 'a' is the digit 10, 'b' is the digit 11, and so on). C++ lets you, the programmer, access this memory address using the address-of operator &. If you place the & before a variable, C++ gives you the address of that variable. (Perhaps appropriately, this looks a lot like the syntax used to declare a reference.)

Naturally, it doesn't make any sense to take the address of something that doesn't have a permanent address, e.g., trying to take the address of a literal value in your code is an error: 

#include <iostream>

int main() {
    std::cout << &42;
    return 0;
}

Here's an example using the address-of operator properly: 

#include <iostream>

int main() {
    int x{5}, y{-6};
    long long z{3};
    int w{42};
    std::cout << &x << '\n' << &y << '\n' << &z << '\n' << &w << std::endl;
    return 0;
}

I just ran this code, and it printed the following:

0x91c13ff6ac
0x91c13ff6a8
0x91c13ff6a0
0x91c13ff69c

If you run the code yourself, you will (almost certainly) get different output, but following a similar pattern. In fact, you will almost certainly get different output every time you run this program, even if you run it repeatedly on the same computer. This is because the program is not assigned the same section of your computer's memory every time it runs, so naturally the variables will have different addresses each time.

The "0x" at the beginning of each address is a standard convention in computer science which indicates that the number is in hexadecimal. Then the number gives the address of the byte where the variable starts. (As mentioned previously, bytes are the smallest addressable units of memory, so we don't get an address for an individual bit.) In the above example, the variable x starts at the address 0x91c13ff6ac. With my compiler (as with almost all modern C++ compilers), an int occupies four bits, so this means that x is stored in bits 0x91c13ff6ac, 0x91c13ff6ad, 0x91c13ff6ae, and 0x91c13ff6af.

After declaring x, we next declared y. Since y is also an int, it also needed 4 bytes of memory, so it started at 0x91c13ff6a8, which is 0x91c13ff6ac - 4; this leaves it exactly the 4 bytes that it needs (0x91c13ff6a8, 0x91c13ff6a9, 0x91c13ff6aa, and 0x91c13ff6ab), so no space is wasted. (For technical reasons, the compiler will sometimes optimize by leaving a little space, but that's not important to us.)

After that, z is a long long, so it needs 8 bytes: 0x91c13ff6a8 - 8 = 0x91c13ff6a0, so z starts at address 0x91c13ff6a0. Finally, w needs 4 bytes, and 0x91c13ff6a0 - 4 = 0x91c13ff69c, so that's the address of w.

The heap

The other section of memory available to a C++ program is called the heap. When possible, we prefer to use the stack, because it is faster to use and generally safer (for reasons we'll discuss later). However, sometimes you need to use the heap. We'll worry about that later.
